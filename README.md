## 💡 项目动机

在日常产品开发中，我们经常遇到这样的问题：

> 🤔 产品经理给出了一段模糊的需求描述，开发团队需要反复沟通才能理清：
> - 用户是谁？要做什么？为什么做？
> - 哪些功能必须有，哪些可以往后排？
> - 有哪些边界和异常情况需要考虑？
> - 怎样才算"做完了"？

**req-decomposer** 就是为了解决这个问题而诞生的 —— 它能将一段模糊的需求描述，自动拆解为四个结构化维度：

| 维度 | 格式 | 作用 |
|------|------|------|
| 📖 用户故事 | As a... I want... So that... | 明确角色、功能与价值 |
| 🎯 功能点列表 | MoSCoW 优先级标注 | 区分 Must / Should / Could / Won't |
| ⚠️ 边界条件 | 异常场景枚举 | 提前发现隐藏风险 |
| ✅ 验收标准 | Given-When-Then | 可测量、可验证的完成定义 |

## ✨ 功能特性

- 🔧 **双模式引擎**：模板模式（离线、零依赖）+ AI 模式（大模型智能分析）
- 📖 **用户故事生成**：自动识别角色，生成标准格式用户故事
- 🎯 **MoSCoW 优先级标注**：智能推断功能点优先级
- ⚠️ **边界条件推导**：基于意图识别，推导常见异常场景
- ✅ **验收标准生成**：输出 Given-When-Then 格式的可测量标准
- 📄 **Markdown 导出**：一键生成结构化需求文档
- 🖥️ **命令行友好**：支持文本/文件输入，终端即时输出

## 🚀 快速开始

### 安装

```bash
# 克隆仓库
git clone https://github.com/Edwadl/req-decomposer.git
cd req-decomposer

# 创建虚拟环境（推荐）
python -m venv venv
source venv/bin/activate  # Linux/macOS
# venv\Scripts\activate   # Windows

# 安装依赖
pip install -e .
```

### 使用

```bash
# 🔹 模板模式 - 直接输入需求文本
req-decomposer -t "管理员必须能够查看系统日志，普通用户可以查询自己的操作记录"

# 🔹 模板模式 - 从文件读取需求
req-decomposer -f requirement.txt

# 🔹 AI 模式 - 调用大模型分析
req-decomposer -t "实现用户登录功能" --mode ai

# 🔹 导出为 Markdown 文件
req-decomposer -f requirement.txt -o output.md

# 🔹 查看帮助
req-decomposer --help
```

**终端输出效果：**

```
🔍 正在分析需求（模式: template）...


📋 需求拆解结果
────────────────────────────────────────────────────────────

📖 用户故事 (User Stories)
────────────────────────────────────────────────────────────
  1. As a 管理员, I want 查看（管理员必须能够查看系统日志），so that 及时获取所需信息，做出合理决策
  2. As a 普通用户, I want 查看（普通用户可以查询自己的操作记录），so that 及时获取所需信息，做出合理决策

🎯 功能点列表 (Functional Points)
────────────────────────────────────────────────────────────
  1. [🔴 Must] 管理员必须能够查看系统日志
  2. [🟢 Could] 普通用户可以查询自己的操作记录

⚠️ 边界条件 & 异常场景 (Edge Cases)
────────────────────────────────────────────────────────────
  1. 查询结果为空时的展示处理
  2. 大量数据加载时的分页与性能
  3. 网络异常导致数据加载失败

────────────────────────────────────────────────────────────

  2. Given 查询条件已设置, When 用户执行查询操作, Then 返回匹配的结果并在3秒内展示

────────────────────────────────────────────────────────────
```

## 🏗️ 技术架构

```
┌──────────────────────────────────────────────────────┐
│                     CLI (Click)                       │
│                  req-decomposer -t/-f                 │
└──────────────────────┬───────────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────────┐
│                 Analyzer (调度层)                      │
│           根据 --mode 路由到对应引擎                    │
└──────────┬───────────────────────┬───────────────────┘
           │                       │
     ──mode template──       ──mode ai──
           │                       │
           ▼                       ▼
┌────────────────────┐  ┌────────────────────┐
│  Template Engine   │  │    AI Engine       │
│  (关键词匹配+模板) │  │  (OpenAI API)      │
│                    │  │                    │
│  • 角色识别        │  │  • Prompt 工程     │
│  • 意图识别        │  │  • JSON 解析       │
│  • 优先级推断      │  │  • 结果校验        │
│  • 模板生成        │  │                    │
└────────┬───────────┘  └────────┬───────────┘
         │                       │
         └───────────┬───────────┘
                     ▼
         ┌────────────────────┐
         │    Formatter       │
         │  (输出格式化)       │
         │                    │
         │  • Terminal 输出   │
         │  • Markdown 导出   │
         └────────────────────┘
```

**设计理念：**

- 🧩 **策略模式**：模板引擎和 AI 引擎实现统一接口，可独立运行、无缝切换
- 🔌 **插件化**：新增分析模式只需实现 `DecomposedResult` 返回即可
- 🛡️ **降级友好**：AI 不可用时自动降级到模板模式，保证始终有输出
